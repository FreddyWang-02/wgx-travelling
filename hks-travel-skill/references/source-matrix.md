# 信息源与证据规则

## 来源矩阵

| 信息 | 首选来源 | 补充与反证 |
|---|---|---|
| 票价、开放时间、预约、证件与规则 | 官方景区、场馆、运营方、政府公告 | 近期权威报道、地图当前状态 |
| 航班、铁路与巴士时刻 | 承运方、机场、铁路官方渠道 | 订单或用户截图、地图交通信息 |
| 地址、坐标、分店与交通关系 | 腾讯位置服务 | 官方地址和第二地图来源 |
| 住宿区域 | 官方交通信息、地图空间关系 | 多位近期独立作者 |
| 氛围、排队、餐饮和体验 | 至少三位近期独立作者 | 地图评论摘要、公开文章、用户材料 |
| 闭店、搬迁、施工与临时关闭 | 官方通知、地图当前状态 | 两条近期独立来源 |
| 天气与季节风险 | 官方气象来源 | 近期本地报道 |

## 查询顺序

1. 城市全貌与区域。
2. 用户兴趣主题。
3. 空间分区与交通。
4. 候选地点的官方动态事实。
5. 闭店、搬迁、排队、施工、差评等反证。
6. 季节、天气和室内备选。

每个正式地点至少保存一个来源链接。相同文案、同一机构转载和互相引用的页面按一条证据计算。

## 时效与置信度

- 航站楼、登机口、值机截止、登机时间和航班动态：6 小时；出发当日再次核验。
- 天气：6 小时。
- 临时通知：24 小时。
- 票价、预约、营业与搬迁：7 天。
- 季节体验和排队：90 天。
- 固定地址：180 天。

动态事实优先使用当前官方来源。`retrievedAt` 只表示抓取日期，不能证明页面内容仍然有效。每条来源同时写入 `freshness.kind`、`checkedAt`、`publishedAt`、`validUntil` 和 `status`。旧年度文章可以支持历史背景或体验判断；涉及当前票价、开放、交通和政策时必须取得近期官方佐证。缺少近期佐证时设置 `status = "needs-recheck"`，界面不得把该事实显示为已确认。

单一社区来源只能形成低置信体验判断。POI 未完成归一时，地点保持候选状态，不进入精确路线。`live` 与 `dynamic` 来源必须填写 `validUntil`；超过有效期后转为 `needs-recheck`。

## 降级

- 网页正文读取失败：保留标题、摘要和 URL，降低置信度。
- 地图服务缺少 Key：先检查宿主地图 MCP 或连接器；仍不可用时保留地点名、地址和待确认坐标，改用绘图式路线图并暂停精确路线计算。
- 社区链接失败：请用户提供可见文字或截图。
- 数据源部分失败：交付已有结果并列明覆盖缺口。
- 认证、验证码、权限和风控错误停止自动重试；普通网络错误最多重试一次。
