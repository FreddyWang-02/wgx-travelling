# WorkBuddy 原生云适配

1. 检查当前会话提供的站点托管、浏览器 Database SDK、宿主身份、集合权限、公开只读查询、发布快照、版本字段、云函数/API、Secret 和对象存储能力。
2. 使用只读查询确认免费额度、当前用户项目归属、所有者写入边界和分享者只读边界。优先使用 WorkBuddy 当前用户身份，不先要求用户提供第三方 Key。
3. 平台要求激活 Database 或云服务时，触发平台官方确认框。只请求完成本次部署所需的最小模块；云函数、Secret 和对象存储均按实际模式选用。
4. 按 [云端数据契约](backend-contract.md) 选择模式：
   - WorkBuddy 有云函数与 Secret：使用 `standard-cloud`。
   - 浏览器 Database SDK 能依据当前用户或项目权限限制写入，并能生成只读分享：使用 `host-native`。
   - 编辑页仅所有者可进入，同时可发布写入被拒绝的只读数据副本：使用 `single-owner-published-share`。
5. 宿主原生模式创建旅行文档，至少保存 `document`、`version` 和 `updatedAt`。发布快照模式额外维护只读副本；分享端对源文档和发布副本都没有写权限。
6. 在加载 `app.mjs` 前注入 `window.TRAVEL_HOST_ADAPTER`，实现 `load()`、`save()` 和可选能力。需要邮箱验证码或 OAuth 的部署同时实现 `prepareEdit()`，在打开新增、编辑和数据弹窗前完成登录。登录框必须使用原生 `<dialog>.showModal()` 或宿主顶层模态能力；发码成功、发码失败、验证码错误、登录成功和取消五条路径都要恢复按钮状态并结束 Promise。部署 `assets/frontend-template/`，无需创建 `/api/e/{token}` 路由。
7. 回传宿主编辑入口和只读分享入口。发布快照模式需说明分享内容在编辑保存后同步发布。
8. 真实浏览器验证未登录编辑预检、验证码按钮恢复、登录成功后保存、取消登录后页面仍可关闭、刷新恢复、分享端无编辑入口且写入被拒绝、旧版本保存提示冲突和五模块。禁止只用已登录会话完成验收。
9. 用户要求附件时单独探测 WorkBuddy 对象存储、公开／受控下载 URL、文件大小限制和分享端读取权限；探针通过后才设置 `capabilities.attachments = true`。只有浏览器数据库且没有对象存储时保持 `false`，前端显示“附件未启用”。
10. 用户指定微信分享时，在微信内置浏览器用正式只读链接完成实机加载。结论只记录“通过”或实际拦截表现；域名白名单、风控或证书原因需要官方证据后才能写入根因。
11. 正式部署时发布 `travel-app-manifest.json`。用户要求新版 Skill 升级时，优先回到原任务或按清单中的 `deploymentId` 定位同一 Sites 项目；保留原 Database 集合、权限、只读发布副本、域名和访问链接。
12. 升级前后各读取一次线上 revision。revision 变化时重新备份和生成升级计划；禁止覆盖用户在升级期间刚保存的内容。更新静态资源时同步更新版本化文件名或查询参数，避免 CDN 与浏览器继续加载旧脚本。
13. 纯代码升级禁止重新初始化旅行文档。升级验收同时打开编辑地址和只读分享地址，并确认 `travel-app-manifest.json`、实际加载资源版本、数据恢复和本次目标修复。

WorkBuddy 只有静态 Sites 且没有持久化数据库时，只能交付 UI 预览。WorkBuddy 数据库缺少写权限隔离与只读发布能力时，继续检查已连接 MCP 或其他免费宿主。
