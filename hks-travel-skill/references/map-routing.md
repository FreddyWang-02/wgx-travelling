# 地图三阶段能力协商与保底路径

宿主 Agent 在研究地点前按 [地图连接器发现、安装与验证](map-connector-setup.md) 检查当前工具和宿主可配置能力。当前列表为空只代表尚未挂载，不能直接进入保底。坐标检索、路线数据、网页底图分别协商并记录结果，禁止用网页底图替代地点检索或真实路线数据。

## 固定优先级

1. 地点与坐标：优先调用 Agent 已有的腾讯地图、高德地图、百度地图、Google Maps 或等价 MCP/连接器；其次使用用户云环境中已配置的地图服务；最后保留地址和待确认坐标。
2. 路线数据：优先调用同一地图服务的步行、驾车或公共交通路线能力。缺少路线能力时，只按 `itineraryItems.order` 绘制游览顺序虚线，并明确标为路线示意。
3. 地图展示：行程默认显示本地绘制地图，编号标记、路线和地点详情读取同一份行程排序。用户切换“网页底图”后，优先通过 `window.TRAVEL_MAP_ADAPTER` 接入宿主已获授权的官方地图 Web SDK；宿主地图不可用时启用 OpenStreetMap 公共瓦片保底，瓦片失败或返回纯色占位内容时回到本地绘制地图。

OpenStreetMap 只承担最终网页底图保底，不能作为默认地点搜索、坐标核验或路线计算服务。使用 `tile.openstreetmap.org` 时必须显示归因、发送正常 Referer、遵守缓存头、禁止预抓取和离线下载；该服务没有 SLA，流量不适合时改用明确授权的 OSM 托管服务或自建瓦片。

## 底图授权门

底图候选进入生产优先级前必须同时满足：

1. 服务商官方文档明确列出该 SDK、API 或瓦片接入方式；
2. 已完成文档要求的开发者注册、Key、安全密钥、域名白名单或 OAuth；
3. 使用方式符合配额、缓存、归因和地图内容展示条款；
4. 页面保留服务商要求的 Logo、版权和来源标识；
5. 连接信息来自用户拥有的宿主 Secret 或服务商认可的前端安全方案。

公开网络可以访问、携带 Referer 能返回图片、文件体积正常或 HTTP 状态为 200 都不构成授权证据。未出现在官方接入文档中的高德、腾讯或其他裸瓦片 URL 不得接入正式产品，也不得描述为“公开免费瓦片”。高德用于中国大陆网页底图时，首选高德官方 JS API 或获得明确授权的官方产品，并按官方要求配置 Web 端 Key 与安全密钥。

## 路径 A：宿主地图能力

当 WorkBuddy 或其他宿主提供腾讯地图 MCP、位置服务连接器或等价地图工具时：

1. 使用宿主工具搜索和归一化 POI，保留名称、地址、服务商 POI ID、原始坐标系和核验时间。
2. 将坐标转换为 TravelPack 要求的 WGS84；无法确认坐标系时不猜测，地点保持待确认。
3. 把核验来源写入 `sources[]`，禁止把宿主凭据、MCP 配置和调用令牌写入 TravelPack。
4. 网页读取 TravelPack 中的地点和坐标；宿主具备地图 Web SDK 时注册 `window.TRAVEL_MAP_ADAPTER`，确保地图标注和路线随行程排序共同刷新。

腾讯位置服务官方 MCP 建立在 WebService API 上，覆盖地点和路线数据。它不加载 JavaScript API GL，也不自动生成 `window.TRAVEL_MAP_ADAPTER`。完成 MCP 接入后如果页面仍显示 OSM，状态应记录为“地点／路线数据已接入，腾讯网页底图未配置”，继续执行 Web Key 与前端适配步骤。

## 路径 B：用户侧腾讯地图 Key

当宿主缺少可用地图工具，且用户需要关键词 POI 搜索时：

1. 引导用户在腾讯位置服务控制台创建属于自己的应用和 Key。
2. 网页底图启用 JavaScript API GL，并将正式部署域名加入精确白名单；Key 写入用户云项目的前端公开配置 `TENCENT_MAP_WEB_KEY`。该 Key 会随官方 SDK 请求出现在浏览器中，安全边界依赖域名白名单。
3. 运行时地点搜索启用 WebService API，Key 只写入用户云项目的 Secret 或环境变量 `TENCENT_MAP_KEY`，由服务端代理返回清洗后的 POI 字段。
4. 两类 Key 都不得写入聊天、TravelPack、日志和导出文件。腾讯结果的 GCJ-02 坐标在保存前转换为 WGS84，网页渲染时再转换为腾讯地图使用的坐标系。

涉及创建账号、开通计费能力或扩大配额时，由用户明确授权后继续。

## 路径 C：网页底图与绘图式路线图

当地图 MCP、连接器和 API Key 在完成发现、安装或配置尝试后仍不可用时：

1. Agent 依据名称、日期、链接、用户材料和研究来源生成地点顺序；坐标无法核实时留空。新增表单不得要求用户手填经纬度，无坐标地点明确不显示地图标注。
2. 网页默认使用 TravelPack 的日期与行程顺序绘制本地路线图；用户主动切换网页底图时再使用 OpenStreetMap 公共瓦片保底。两者都不声称虚线是真实道路、距离或耗时。
3. 地点列表、备注、时间、资料关联和结构化维护保持可用。
4. 后续获得地图能力后补齐坐标，网页自动恢复地理地图。

## 选择结果

向用户报告以下状态之一：

- `host-map-capability`：由宿主地图工具生成 POI。
- `user-tencent-key`：由用户云环境的腾讯地图 Key 提供搜索。
- `osm-basemap-fallback`：宿主地图 Web SDK 不可用，网页使用 OpenStreetMap 保底底图。
- `schematic-fallback`：使用无 Key 绘图式路线图。
- `connector-installable`：已找到可配置地图 MCP，正在等待必要授权或 Key。
- `fallback-after-setup-attempt`：连接器发现与配置尝试均已完成，允许进入保底。

这些状态只改变地点获取和地图展示能力，不改变 TravelPack 1.1、网页维护流程和用户数据归属。

## 真实渲染验收

底图验收必须在与线上相同来源、CSP、Referer 和域名环境中执行，至少覆盖一个地标清晰的已知坐标。浏览器截图应同时出现可辨识的道路或地标、服务商归因、路线和编号标记；缩放一级并平移后再次确认内容更新。纯色、透明、棋盘格或重复占位瓦片均视为失败。网络状态码、Content-Type 和文件大小只作为辅助证据，不能替代浏览器渲染检查。
